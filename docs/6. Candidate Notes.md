## 1. Elevator Pitch

**The Problem:** A slide deck has to answer four probability questions about Steph Curry's 2022-2023 shots - how often he scores, how often a short sequence falls a certain way, what happens *given* a shot type, and what a made shot tells you *looking backward* - and every number on those slides is graded against a rubric for correctness. The binomial questions can be answered two different ways, and the conditional ones can be answered two different ways; if those routes disagree, one of them is wrong and the deck cannot say which.

**The Solution:** A single reproducible script, `curry_analysis.py`, executes the project brief in order: it downloads the CSV from the Udacity CDN with `requests`, verifies it is non-empty, loads it with pandas, normalizes `result`/`lead` to booleans and `shot_type` to integers with integrity assertions, prints the inspection suite (`shape`, `dtypes`, `head`, `value_counts`), computes the overall frequencies, evaluates both binomial questions by the manual `C(n,k)·pᵏ(1−p)ⁿ⁻ᵏ` formula *and* `scipy.stats.binom.pmf`, prints the four required assumptions with an honest discussion of whether they hold, then computes every conditional probability twice - once by direct counting and once through Bayes' Theorem - so agreement is demonstrated rather than assumed. The retrospective answers are derived through Bayes with every intermediate value on its own line, and the whole run is mirrored into `curry_probability_summary.txt`.

**The Result:** From **1,434 attempts**: P(Make) **0.4902**, P(Miss) **0.5098**, P(3-pointer) **0.5481**, P(2-pointer) **0.4519**. Binomial: exactly 3 of the next 4 made = **0.2402**, exactly 4 of the next 5 threes = **0.2039** (manual formula and `binom.pmf` agree to ~1e-17). Future conditionals: P(Made|3) **0.4186**, P(Lead|3) **0.4936**, P(Made|2) **0.5772**, P(Lead|2) **0.5154** - each reproduced by Bayes' Theorem to ~1e-16. Past conditionals: P(3|Made) **0.4680**, P(2|Made) **0.5320**, summing to **1.000000**. Every figure was recomputed by a second, independent implementation: **47 checks, 0 failures**.

### Key Design Decisions

| Decision | Rationale |
| :--- | :--- |
| **Normalize defensively, then assert** | The brief warns `result`, `shot_type` and `lead` "may be string or bool". The conversion helper handles native bools, `"TRUE"`/`"FALSE"` strings, and numeric flags - and a hard `ValueError` fires if `shot_type` ever contains something other than 2 or 3. Correct output on a differently-encoded copy of the file is a requirement, not a nicety. |
| **Check for nulls before touching the data** | `_to_bool()` maps NaN to `False`, so a missing `lead` would otherwise be silently reported as "no lead" and the later `isna()` print would show zeros. The null check now runs first and aborts the run. An integrity check that runs after the mutation it is supposed to detect is decorative. |
| **Compute every conditional twice - by counting and by Bayes** | The rubric grades Bayes' rule separately from conditional probability. Each quantity is therefore derived both ways in the same section and the two values are printed side by side with their absolute difference, so "the theorem was applied correctly" is demonstrated rather than asserted. |
| **Show the binomial two ways as well** | `math.comb`-based manual arithmetic and `scipy.stats.binom.pmf` are independent code paths; printing both with their difference (≈2.8e-17) catches transcription slips in either the formula or the call signature. |
| **Round only at output time** | All arithmetic runs at full precision; a single `fmt()` helper applies the 4-decimal rule when text is produced. P(3 | Made) is computed from unrounded inputs, then displayed - so the printed 0.4680 is a rounding of the true value, not of a pre-rounded one. |
| **Mirror the whole run through one stream** | A `Tee` writer sends every `print()` to stdout and to `curry_probability_summary.txt` at once, and the final confirmation line is emitted while the file is still open. The deck and the console can never disagree, because there is only one output path. |
| **Idempotent download with a loadable-file confirmation** | Re-runs reuse a non-empty CSV instead of re-downloading, and both branches print the row count and column names through pandas right after Step 1, as the brief requires. A zero-byte or HTML-error response can never be mistaken for the dataset. |
| **Keep raw and derived artifacts separate** | `stephen_curry_shots_2023.csv` is stored byte-for-byte as downloaded; `curry_probability_summary.txt` is derived. A reviewer can re-run the analysis against the original bytes. |

## 3. Analytical Principles in Practice

**Conditioning direction is the whole lesson - so both directions are labelled.** P(Made|3) = 0.4186 and P(3|Made) = 0.4680 are different questions about the same joint probability: the first asks "of the threes, how many went in," the second "of the makes, how many were threes." The output always prints the conditioning bar (`P(A | B)`), never just the pair of letters, because swapping the direction is the single most common way to answer this slide wrong.

**Denominators belong next to every count.** "329 made threes" means nothing without "out of 786 threes" (and both out of 1,434 shots). Every conditional line in the report shows its numerator, its denominator, and the resulting probability, so any figure can be re-divided by hand from the same page.

**Two routes to the same number beat one careful route.** For all four forward conditionals and both binomial questions, the printed value is the *agreement* of two independent computations - direct counting vs. Bayes' Theorem, manual formula vs. `scipy`. When both routes print the same six decimals, the probability that one of them contains a systematic error is essentially nil.

**The binomial model is a simplification, and the report says so out loud.** The rubric asks directly whether the assumptions are violated. Assumptions 1 (fixed n) and 2 (binary outcome) hold exactly; assumption 3 (independence) is the weak one - hot-hand streaks, defensive adjustments and fatigue couple consecutive shots; assumption 4 (constant p) is violated in spirit, because a layup and a 30-footer share one season-wide `p`. Stating this keeps the numbers framed as approximations under an "all shots alike and independent" model rather than as forecasts.

**Report the counter-intuitive result instead of the expected one.** Curry attempts 54.8% threes but makes only 46.8% of them; his two-pointers go in at 57.7% against 41.9% for threes. The deck-facing summary presents both conditional probabilities plainly so the reader can see volume and efficiency pulling in opposite directions - the point of the exercise is to compute, not to confirm a narrative about three-point shooting.

**Descriptive probabilities, no causal claims.** Nothing here says taking a three *lowers* his chance of scoring, or that leading *causes* different shot selection. The numbers describe these 1,434 attempts only; the lead split (722 vs. 712) is nearly even, so there is no selection imbalance to hide either.

**Percentages are a courtesy, decimals are the grade.** Every probability appears as a 4-decimal value and as a percentage computed from that same value, so a reader can quote either format without re-deriving it - and the verification pass checks the percentage consistency of every such pair in the file.

## 4. AI Collaboration Playbook

The deliverable was a slide deck whose every figure had to match a reproducible computation, so the workflow was built around an evidence hierarchy: **source CSV → executed script → summary text → slide deck**.

Worth stating plainly: P1's pipeline split the work across two models (DeepSeek V4.1 drafted the script; MiMo reviewed it). **P2's implementation was authored and reviewed inside a single MiMo session**, which weakens the "a second model caught the first one's mistakes" property that P1 relied on. The workflow was therefore restructured around artifacts instead of personalities:

1. **Plan first, then code.** The seven-step plan (download → clean → overall → binomial → future conditionals → retrospective Bayes → summary) was written out and approved before any file existed, so the implementation had an agreed specification to be judged against - `docs/5. Rubric.md` served the same role afterwards.
2. **The rubric was treated as the acceptance test.** Each criterion - binomial correctness, conditional correctness, Bayes correctness, assumptions provided, plus the two "standout" suggestions - was checked against what the executed artifact actually contains, not against what the code intends.
3. **An independent second implementation was written from scratch** for the review: pure standard library (`csv` + `math.factorial` for the binomial, no pandas, no scipy, no shared helper), re-deriving every reported count and probability from the raw CSV and matching it against the text of `curry_probability_summary.txt`. Agreement between two independent computations is the check; agreeing with yourself is not. **47 checks, 0 failures.**
4. **Behavior was tested, not read.** Three spec-conformance defects found in review were fixed and the whole pipeline was re-executed: a fresh-from-CDN run in a clean directory (exit 0), a console-vs-file byte comparison (now identical), and a fault-injection run with a null planted in `lead` (the script aborts with a precise `ValueError` instead of quietly scoring the shot as "no lead").
5. **The narrative was checked back against the artifact.** No number appears in this document or the README that `curry_probability_summary.txt` does not contain.

The key collaboration principle is **verify, don't trust**: the reviewing pass never accepted a figure because the drafting pass asserted it - it recomputed it with different tools - and it reported the defects it found, including three that were in the verifier itself.

## 5. Evaluation & Verification Philosophy

**Executed outputs are the evidence.** All reported figures - 1,434 shots, 703 makes, 786 threes, the joint counts 329/388/374/334, 0.240241, 0.203934, 0.418575, 0.493639, 0.577160, 0.515432, 0.467994, 0.532006, the 1.000000 sanity sum - were read from a completed run of `curry_analysis.py`, not estimated or recalled.

**Two independent implementations beat one careful one.** The verification pass re-derived every statistic from the raw CSV with different tools (`csv.DictReader` instead of pandas, a `math.factorial`-based binomial instead of `scipy.stats.binom`) and required agreement at the printed precision before any rubric criterion could be marked satisfied. It also checked identities that no single formula proves: P(Make)+P(Miss) = 1, P(3)+P(2) = 1, P(3|Made)+P(2|Made) = 1, and the total-probability collapses P(Made|3)·P(3) + P(Made|2)·P(2) = P(Made) and P(3|Lead)·P(Lead) + P(2|Lead)·P(Lead) = P(Lead).

**The verifier is code too, and it fails like code.** The first verification run reported 3 failures out of 44 - all three traced to the verifier: two regexes that matched the first of two repeated output lines, and one identity the verifier itself had mis-specified (`P(3|Made)·P(3)` instead of `P(Made|3)·P(3)`). Each was corrected and the suite re-run to 47/47. Recording this matters because a green checkmark from a buggy checker is worse than no check: the defect belongs to whoever writes the test.

**Check the rubric against the artifact, not against the intent.** The review below walks the four rubric criteria and both standout suggestions one by one against what actually exists in `curry_probability_summary.txt`, and separately against the source in `curry_analysis.py` for requirements that are structural (headers in comments *and* output, `math` imported for `C(n,k)`, no hardcoded probabilities).

**Rounding is a presentation rule, not a computation rule.** The brief asks for four decimal places; the script rounds once, inside `fmt()` at the moment text is produced, and the verifier confirms the displayed value is the correct rounding of the independently computed one - so the deck's numbers and the script's numbers are the same numbers.

**Every probability is derived, never embedded.** No literal probability exists anywhere in `curry_analysis.py`; even the slide labels take `k` and `n` from the binomial variables they describe. The only constants are structural: the dataset URL, file names, and the n/k values that the project brief itself specifies (4 choose 3, 5 choose 4).

**The dataset's limits are disclosed, not hidden.** These are Curry's attempts in one season - a convenience sample, not a random sample of all shots he could take - and the report frames the binomial answers as model-dependent approximations accordingly.

## 6. Challenges & Resolutions

### Challenge 1 - The spec warns the columns "may be" strings or booleans

**What happened:** The brief says `result` and `lead` are `"TRUE"`/`"FALSE"` and `shot_type` is `"2"`/`"3"` "may be string or bool/int or string". The delivered CSV turned out to be already typed (bool, bool, int64) - which is exactly the trap: code written against what *this* file looks like breaks silently on the Google Sheets export or a re-downloaded copy where the same columns arrive as text, flipping every `== True` comparison to `False` and zeroing out the make rate.

**Resolution:** A single conversion helper accepts native bools, `"TRUE"`/`"false"`-style strings, and numeric flags, and `shot_type` is cast through `astype(int)`. After normalization, an assertion rejects any `shot_type` value outside {2, 3}, and `value_counts()` for all three columns is printed as evidence. The cost is a few lines; the benefit is that a re-encoded dataset produces the same answer or a loud error - never a quiet wrong one.

### Challenge 2 - Bayes' Theorem is easy to assert and hard to prove

**What happened:** The rubric grades "correct use of Bayes' rule" separately from "correct conditional probability calculations," and the brief asks for all four future conditionals *plus* both retrospective ones. A script could print `P(Lead|3) = 0.4936` once and call it done - but then nothing demonstrates that Bayes was used, and a sign error in the theorem (swapping `P(A)` and `P(B)` is the classic one) would pass unnoticed.

**Resolution:** Every conditional is computed twice inside the same section and both routes are printed: direct counting (`388/786`) and the theorem (`P(3|Lead)·P(Lead)/P(3)` = `0.537396 × 0.503487 / 0.548117`), followed by their absolute difference (≈1.1e-16) and a YES/NO match flag. The retrospective pair gets the full treatment required by the brief - notation mapping first, then five numbered intermediate lines each - and ends with the total-probability sanity check `0.467994 + 0.532006 = 1.000000`. If either route were wrong, the page would show it.

### Challenge 3 - The binomial assumptions do not really hold

**What happened:** The rubric asks for the four assumptions *and*, as a standout, whether they are violated and why. The honest answer for basketball is that two hold and two do not: trials are not truly independent (streaks, fatigue, defensive schemes) and `p` is not truly constant (a layup and a 28-footer share one season-wide rate of 0.4902). Glossing this would be the easier path and the weaker submission.

**Resolution:** §4C prints the four assumptions as a numbered list and then discusses each one specifically - which are exact, which are approximations, and what that means for interpreting 0.2402 and 0.2039 ("ballpark estimates under an 'all shots alike and independent' model, not exact forecasts"). The summary section repeats the caveat in one line so the deck can quote it directly.

### Challenge 4 - The console and the saved file disagreed

**What happened:** The brief requires the *entire* printed output to be saved to `curry_probability_summary.txt`. The original implementation wrote the file through a capture stream but printed the final confirmation line outside it - so the console ended with 286 lines and the file with 284. A grader diffing the two, or comparing the file against a console transcript, would find a discrepancy that no calculation would explain.

**Resolution:** The confirmation line is now emitted while the summary file is still open, so both destinations receive every byte. Re-running now produces a console transcript and a file that are byte-identical (289 lines each), which the review verified with a line-by-line `Compare-Object` diff.

### Challenge 5 - The missing-data check ran after the data was mutated

**What happened:** The audit found an ordering bug with no effect on this dataset but a real effect on trust: `_to_bool()` coerces NaN to `False`, and it ran *before* the printed `isna()` report - so a null in `result` or `lead` would have been silently converted into a legitimate-looking value, and the "Missing values in key columns" line would still have printed zeros. The integrity check could not have failed, which is the same as not existing.

**Resolution:** The null check now runs before any conversion and raises `ValueError: Missing values in key columns: {'lead': 1}` naming the offending column. The fix was proven by fault injection - a copy of the CSV with one `lead` cell emptied aborts immediately, while the intact dataset still runs clean. This is also the concrete reason the review treats "checks that cannot fail" as defects.

## 10. Retrospective

### What I'd Do Differently

1. **Cross-check with a spreadsheet, as the course suggests.** `docs/4. Tools and Resources.md` supplies `COUNTIF`, `COUNTIFS` and `BINOMDIST` formulas precisely so a second, human-visible tool can confirm the answers. The Python verification is independent in code but not in *medium*; pasting `=BINOMDIST(3,4,703/1434,FALSE)` into Sheets would close the loop the course intended.
2. **Add cumulative binomial results.** "Exactly 3 of 4" answers the brief, but "at least 3 of 4" is what a fan actually asks; `binom.sf(2, 4, p_make)` and `binom.cdf` would cost one line and preempt the question.
3. **State the conventions in the output.** The report never says that quartiles/quantile conventions or the sample definition matter here; adding a line such as "probabilities are MLE estimates from 1,434 attempts; `binom.pmf` with p = k/n" would preempt a reviewer asking how `p` was obtained.
4. **Quantify the independence worry instead of only discussing it.** §4C argues that streaks and fatigue weaken independence; computing the observed make-rate after makes vs. after misses from the sequence of shots would turn that argument into a measurement - a natural, defensible extension that stays within descriptive statistics.
5. **Report confidence intervals alongside the rates.** P(Make) = 0.4902 is a point estimate from 1,434 trials; a Wilson interval would show how much of the 0.5772 vs. 0.4186 gap between shot types is sampling noise and how much is real - the obvious next step from description toward inference.

### What Worked Well

1. **Computing every conditional twice.** Direct counting vs. Bayes' Theorem (and manual formula vs. `scipy`) means no single code path can silently own the answer; the printed differences (~1e-16, ~1e-17) convert "trust me" into evidence, and it is what makes the Bayes criterion unambiguous to grade.
2. **A verifier that shares nothing with the script.** `csv` + `math.factorial` instead of pandas + scipy means a pandas-specific or scipy-specific mistake cannot hide in both places - and it caught nothing in the arithmetic while catching three real spec-conformance defects in the pipeline.
3. **Treating the verifier's own failures as findings.** Three initial FAILs turned out to be bugs in the checker (duplicate-regex indexing, a mis-specified identity). Fixing the checker rather than relaxing the threshold kept the 47/47 result meaningful.
4. **The `Tee` output stream.** One writer feeding console and file simultaneously makes "the summary matches the run" a structural property instead of a discipline - and made the byte-identity check trivial to prove.
5. **Null-check-before-mutation, proven by fault injection.** Moving the check was one edit; *proving* it fires (planted null → `ValueError`) is what distinguishes a fixed bug from a moved one.
6. **Idempotent download with a pandas confirmation.** Re-runs never re-download a good file, fail loudly on a bad one, and Step 1 now prints the row count and column names the brief asks for - in both branches.

### The AI Partnership

> "The value of the AI partnership here was a division of labor the rubric rewards, reorganized for a single-model session: the assistant drafted the plan, got it approved *before* writing code, implemented the seven steps, and then audited its own work as if it were someone else's - treating `docs/5. Rubric.md` as the acceptance test and re-deriving every number with a second implementation that shared no code or libraries with the first. Because one model reviewing itself is weaker evidence than two models checking each other, the review substituted artifacts for personalities: independent recomputation, a fresh-from-CDN run in a clean directory, a byte-level diff of console against file, and a fault-injected null to prove a guard actually fires. That process found zero arithmetic errors and three non-numeric defects - a spec confirmation printed one step too late, an integrity check that ran after the data it policed had already been mutated, and a saved file that trailed its own console output - plus three false failures originating in the verifier itself. The lesson cuts both ways: correctness has layers (value, structure, presentation, and the checker's own honesty), and only the first one gets checked automatically. The human role was to demand the verification plan, to insist the binomial assumptions be argued rather than listed, and to keep the interpretation proportional - probabilities over 1,434 real attempts, approximations under a simplified model, and a retrospective question whose answer is 46.80% of the makes, not a statement about how Curry plays."

### Final Thoughts

I followed the project's core discipline end to end: download and verify the source, inspect and normalize before computing, classify every assumption and defend it, compute each probability by the method the brief specifies *and* by an independent alternative, show the intermediate values instead of asserting the theorem, and write the four slide sections with every figure at four decimals plus its percentage.

The most useful engineering lesson is the one the audit taught: **a correct number can still sit inside a broken report.** Not one of the 47 checked values was wrong, yet the review still found a confirmation printed in the wrong step, an integrity check incapable of failing, and a saved file that disagreed with its own console. Statistics that satisfy the arithmetic rubric still fail the specification rubric if the artifact does not do exactly what the brief asked - so the fix list was cleared, the pipeline was re-run end to end, and this document quotes only figures that a second, independent implementation reproduced from the raw CSV.
